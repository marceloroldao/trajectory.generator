# Full-universe streaming trajectory address — 2026-09-20

## Result

The phase-lifted topological universe can be addressed directly as one public
finite-state transition graph.

No special transient-to-core handoff is required.

The codec uses:

- the complete public phase-lifted graph;
- the public set of eight valid initial nodes;
- the physical transition count;
- one integer address.

At every step, incoming graph edges partition the exact path family ending at
the current node into public contiguous rank blocks. Forward evolution inserts
the predecessor rank into the selected edge block. Reverse evolution identifies
the predecessor edge from the block that contains the current rank.

## Initial nodes

The historical topological universe starts after a three-bit prefix.

For each 3-bit history state `h`, the public lifted initial node is:

```text
(h, initial_topology(h), phase=0)
```

There are exactly eight such nodes, accounting for the `2^3` possible initial
three-bit prefixes.

After that prefix, one graph edge corresponds to one additional physical bit.

Therefore:

```text
trajectory length n = 3 + graph transition count
```

## Exact count identity

For every tested physical length, the new streaming graph count is identical to
the historical dynamic-program count:

```text
streaming_count(n - 3) == historical_count(n)
```

for all checked `n` through the first 63-bit overflow of each candidate.

This is stronger than matching one frontier number: the two constructions count
the same admissible language at every checked length.

Small-horizon exhaustive language-set comparison also matches exactly: every
bit trajectory generated by the historical batch unranker appears once in the
streaming graph codec, and no extra trajectory appears.

## Reverse reconstruction

Decoding the final integer address at physical transition time `t` returns:

1. the public initial lifted node;
2. every traversed physical graph edge, in order;
3. every intermediate phase-lifted causal node.

For this universe, the emitted bit is recoverable from the target history state:

```text
bit = target_history & 1
```

The three bits encoded in the initial history plus one bit per graph transition
reconstruct the complete binary trajectory.

Thus the operational path is:

```text
(final_address, trajectory_length)
    -> initial lifted node
    -> complete graph-edge history
    -> complete bit trajectory
```

without storing the trajectory or the core-entry point as side metadata.

## Relationship to the recurrent-core pipeline

The recurrent-core pipeline remains useful because it exposes the geometry of
the universe:

- recurrent SCCs;
- entropy-bearing branch nodes;
- deterministic flights;
- information-clock macro-edges;
- asymptotic growth.

But the full-universe address no longer needs to switch representations at the
core boundary. It can operate over the complete public graph from the initial
prefix onward.

## Critical interpretation

This result should be stated precisely.

It **does demonstrate** an online reversible address state derived from the
public universe, with local one-edge reverse steps and exact capacity matching
the historical admissible trajectory family.

It **does not demonstrate** that the universe's raw causal node
`(history, topology, phase)` by itself contains the complete past.

The final integer is an additional enumerative address state. Its update law is
derived entirely from public path counts of the universe graph, but it is still
a constructed address coordinate.

This distinction matters for the deeper trajectory.generator hypothesis.

## Computational cost

The current reference implementation caches:

```text
D(v,t) = exact public path count ending at node v at time t
```

for all graph nodes and times reached.

For a graph with `V` nodes and horizon `T`, the reference memory cost is
`O(V*T)` big integers. Reverse work per physical step is proportional to the
number of incoming edges of the current node.

This count cache contains no trajectory-specific history; it is deterministic
public law data. Nevertheless, reducing or eliminating the `O(V*T)` cache is
the next important implementation problem.

## Count-field table follow-up: completed

The `O(V*T)` public count table is no longer required for the phase-lifted
topological candidates.

`trajectory_generator/count_field_recurrence.py` derives an exact minimal
Krylov recurrence for the endpoint-count vector and
`trajectory_generator/floquet_count_field.py` compresses it further onto the
public phase-0 Floquet slice.

The Floquet variant:

- keeps no persistent seed basis;
- regenerates distant count rows from the graph and recurrence coefficients;
- walks the count field backward with a short fixed window during decode;
- preserves exactly the same addresses, languages, and 63-bit frontiers.
