# Experimental result — injectivity frontier through 21 bits

Date: 2026-08-19
Status: pre-alpha experimental evidence
RSMS compatibility: pending central specification mapping

## Research question

Can the original ordered bit trajectory be uniquely identified from only:

1. the final 63-bit machine state; and
2. the number of data steps?

No trajectory log, checksum, plaintext hint, side table, or auxiliary index is used by the decoder hypothesis.

## Configuration

The tested machine is the default configuration in `trajectory_generator/core.py`:

- state width: 63 bits;
- initial state: 0;
- deterministic universe period: 3 steps;
- bit 0: no data perturbation after the universe transition;
- bit 1: reversible, time-dependent modular/rotational perturbation;
- no golden-ratio constant in the dynamics.

The universe and data transformations are deterministic and fully specified by the repository code. The number of steps is treated as external metadata and is part of the decoding key `(final_state, steps)`.

## Method

The experiment propagated the complete state frontier incrementally. Starting from the single initial state, every state at depth `n` was branched with input bits 0 and 1 to build depth `n+1`. A duplicated state at the same depth is an exact collision: two different trajectories with the same step count produce the same final state.

This method is exhaustive for every reported depth; it is not random sampling.

## Results

| bits | trajectories | unique final states | collisions | injective |
|---:|---:|---:|---:|:---:|
| 17 | 131,072 | 131,072 | 0 | yes |
| 18 | 262,144 | 262,144 | 0 | yes |
| 19 | 524,288 | 524,288 | 0 | yes |
| 20 | 1,048,576 | 1,048,576 | 0 | yes |
| 21 | 2,097,152 | 2,097,152 | 0 | yes |

Earlier exhaustive checks also found zero collisions through 16 bits.

## Interpretation

Within the tested domain, the mapping

`trajectory -> (final_state, steps)`

is injective. Therefore, for lengths up to 21 bits under this exact machine configuration, a unique inverse exists in principle from `(final_state, steps)` alone.

This does **not** establish scalable recovery. The current exact decoder is exponential, and no claim is made that the mapping remains injective beyond the tested frontier.

## Information-theoretic limit

For a fixed step count `n > 63`, there are `2^n` possible binary trajectories but only `2^63` final machine states. Therefore a 63-bit final state cannot uniquely represent every arbitrary `n`-bit trajectory when `n > 63`, even if the step count is known. By the pigeonhole principle, collisions must exist no later than the full 64-bit trajectory domain for a fixed 63-bit state width.

The research problem is consequently split into two parts:

1. determine the empirical injectivity frontier and collision structure for this finite-state machine;
2. investigate whether a structurally constrained trajectory family, a larger state width, or a different reversible address construction can extend useful recoverability without storing trajectory-side information.

## Reproduction

Run:

```bash
python experiments/frontier_scan.py --from-bits 17 --max-bits 21
```

The scanner records a witness pair automatically when the first exact collision appears.
