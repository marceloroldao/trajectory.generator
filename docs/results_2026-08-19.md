# Experimental result — injectivity frontier through 22 bits

Date: 2026-08-19
Status: pre-alpha experimental evidence
RSMS compatibility: pending central specification mapping

## Research question

Can the original ordered bit trajectory be uniquely identified from only:

1. the final machine state; and
2. the number of data steps?

No trajectory log, checksum, plaintext hint, side table, or auxiliary index is used by the decoder hypothesis.

## Configuration

The primary tested machine is the default configuration in `trajectory_generator/core.py`:

- state width: 63 bits;
- initial state: 0;
- deterministic universe period: 3 steps;
- bit 0: no data perturbation after the universe transition;
- bit 1: reversible, time-dependent modular/rotational perturbation;
- no golden-ratio constant in the dynamics.

The universe and data transformations are deterministic and fully specified by the repository code. The number of steps is treated as external metadata and is part of the decoding key `(final_state, steps)`.

## Method A — exact 63-bit frontier

The experiment propagated the complete state frontier incrementally. Starting from the single initial state, every state at depth `n` was branched with input bits 0 and 1 to build depth `n+1`. A duplicated state at the same depth is an exact collision: two different trajectories with the same step count produce the same final state.

This method is exhaustive for every reported depth; it is not random sampling.

## Results A

| bits | trajectories | unique final states | collisions | injective |
|---:|---:|---:|---:|:---:|
| 17 | 131,072 | 131,072 | 0 | yes |
| 18 | 262,144 | 262,144 | 0 | yes |
| 19 | 524,288 | 524,288 | 0 | yes |
| 20 | 1,048,576 | 1,048,576 | 0 | yes |
| 21 | 2,097,152 | 2,097,152 | 0 | yes |
| 22 | 4,194,304 | 4,194,304 | 0 | yes |

Earlier exhaustive checks also found zero collisions through 16 bits.

### Interpretation

Within the tested 63-bit domain, the mapping

`trajectory -> (final_state, steps)`

is injective through 22 bits. Therefore, for lengths up to 22 bits under this exact machine configuration, a unique inverse exists in principle from `(final_state, steps)` alone.

This does **not** establish scalable recovery. The current exact decoder is exponential, and no claim is made that the mapping remains injective beyond the tested frontier.

## Method B — state-width collision sweep

To study how collisions emerge, the same dynamics and constants were tested with smaller state widths. For each width, the complete frontier was expanded until the first exact duplicate final state appeared.

## Results B — first observed exact collision

| state width | first collision at trajectory length | total trajectories at that length | unique final states | duplicate count |
|---:|---:|---:|---:|---:|
| 16 | 10 | 1,024 | 1,018 | 6 |
| 24 | 14 | 16,384 | 16,380 | 4 |
| 32 | 17 | 131,072 | 131,070 | 2 |

First collision witnesses recorded during the run:

- width 16, length 10: trajectories `0110001100` (396) and `0111001011` (459) -> final state `41550`;
- width 24, length 14: trajectories `00000100001000` (264) and `00110111100111` (3559) -> final state `4132560`;
- width 32, length 17: trajectories `00100000011110001` (16505) and `11010010101110000` (107888) -> final state `4143545117`.

### Interpretation of the width sweep

The collision onset moves later as the state width grows, but in these tests it appears well before `n = width`. That behavior is qualitatively consistent with birthday-collision scaling for a well-mixed finite mapping, where collisions often become likely after exploring on the order of `2^(w/2)` states rather than only after all `2^w` states are exhausted.

This is an empirical comparison, not proof that the 63-bit machine behaves exactly like a random mapping. Extrapolating the smaller-width results suggests that the 63-bit critical region may occur around trajectory lengths in the low 30s, but that remains a hypothesis until an exact collision is found.

## Information-theoretic limit

For a fixed step count `n > 63`, there are `2^n` possible binary trajectories but only `2^63` final machine states. Therefore a 63-bit final state cannot uniquely represent every arbitrary `n`-bit trajectory when `n > 63`, even if the step count is known. By the pigeonhole principle, collisions must exist no later than the full 64-bit trajectory domain for a fixed 63-bit state width.

The research problem is consequently split into two parts:

1. determine the empirical injectivity frontier and collision structure for this finite-state machine;
2. investigate whether a structurally constrained trajectory family, a larger state width, or a different reversible address construction can extend useful recoverability without storing trajectory-side information.

## Reproduction

Primary frontier:

```bash
python experiments/frontier_scan.py --from-bits 17 --max-bits 22
```

Width sweep:

```bash
python experiments/width_frontier_scan.py --widths 16 24 32 --max-bits 21
```

The scanners record witness pairs automatically when exact collisions appear.

## Next tests

- search for the first 63-bit collision using lower-memory collision algorithms instead of retaining the full frontier;
- test widths 40 and 48 to verify the apparent width-versus-collision trend;
- measure sensitivity to trajectory order at fixed Hamming weight;
